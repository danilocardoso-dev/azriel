# AZRIEL — Engineering Core v0.7 — Assembly Intelligence

Status: **implementada; validação operacional pendente**.

## Objetivo

A v0.7 adiciona uma camada semântica persistente sobre os componentes reais do modelo 3D. A geometria continua imutável e vem do GLB/GLTF; rótulos, funções, subsistemas, descrições, notas e relações são armazenados separadamente no SQLite.

```text
GLB / GLTF
↓
Model Core + Component Core
↓
identidade estável do modelo e do componente
↓
Assembly Intelligence (SQLite)
↓
UI operacional + ferramentas READ do AI Core
```

## Identidade e persistência

O `modelIdentity` é o SHA-256 dos bytes do modelo. O caminho local do arquivo não é persistido. Cada componente recebe uma identidade estrutural composta pelo caminho hierárquico, tipo, nome original e ordinal entre irmãos equivalentes.

A migration `0010_assembly_intelligence.sql` cria:

- registro de modelos conhecidos;
- registro das identidades estruturais dos componentes;
- semântica por componente;
- subsistemas com hierarquia opcional;
- relações direcionais entre componentes.

O backend valida os componentes contra o registro do modelo. Relações autorreferentes, duplicadas, com tipo inválido ou alvo externo ao modelo são rejeitadas.

## Interface

O Engineering View preserva viewport, gestos, Component Core, Exploded View e comandos visuais. A área `ASSEMBLY INTELLIGENCE` oferece:

- `MODEL`: identidade e resumo do modelo;
- `COMPONENTS`: lista pesquisável, filtros e editor do componente selecionado;
- `ASSEMBLY`: relações e grafo SVG sincronizado com a seleção 3D;
- `SEMANTICS`: cadastro e hierarquia de subsistemas;
- exportação manual de um snapshot JSON.

A pesquisa considera nome original, rótulo semântico, função e subsistema. A cobertura usa somente componentes selecionáveis:

- `UNCLASSIFIED`: sem rótulo;
- `PARTIAL`: rótulo preenchido, mas função ou subsistema ausente;
- `CLASSIFIED`: rótulo, função e subsistema preenchidos.

## AI Core

Foram adicionadas sete ferramentas somente leitura:

```text
get_component_semantics
get_subsystems
get_subsystem_components
get_component_relationships
get_unclassified_components
get_semantic_coverage
get_assembly_graph_summary
```

Referências contextuais usam o componente selecionado. O AI Core não pode criar, editar ou excluir semântica e não recebe acesso ao banco, ao arquivo do modelo ou aos objetos Three.js.

## Privacidade e integridade

- nenhum frame de câmera é persistido ou transmitido;
- nenhum caminho local entra na camada semântica;
- o GLB/GLTF original não é alterado;
- a exportação JSON ocorre apenas por ação manual do operador;
- semântica de um modelo não é aplicada a outro hash;
- nomes técnicos genéricos não recebem significado automático.

## Limitações

- importação JSON e edição direta no grafo não fazem parte desta versão;
- o grafo visual limita a renderização a 80 componentes para manter legibilidade;
- alterações estruturais que produzam novo hash são tratadas como outro modelo e exigem revisão manual;
- a calibração gestual continua pendente para v0.2.1.

## Como validar

1. carregar um GLB/GLTF real;
2. criar ao menos dois subsistemas;
3. selecionar peças na árvore, viewport e lista semântica;
4. preencher rótulo, função, descrição e notas;
5. criar uma relação válida e confirmar o grafo;
6. tentar relação duplicada e autorreferente;
7. filtrar por status e subsistema;
8. exportar o JSON;
9. fechar e reabrir o Azriel, recarregar o mesmo arquivo e confirmar os dados;
10. perguntar ao AI Core sobre função, subsistemas, relações e cobertura;
11. confirmar que MOVE, ROTATE, SCALE, Exploded View e ferramentas visuais da v0.6 continuam funcionando.
